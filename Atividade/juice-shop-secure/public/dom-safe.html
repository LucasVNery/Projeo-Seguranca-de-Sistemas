Comparação: Vulnerável vs Seguro

❌ Código Vulnerável

// innerHTML EXECUTA HTML arbitrário
const filter = location.hash.slice(1);
document.getElementById('output')
  .innerHTML = decodeURIComponent(filter);

// Payload na URL:
// page.html#<img src=x onerror=alert(1)>
// → cria elemento real, dispara onerror

O payload no fragment é interpretado como HTML e executa o handler de evento.

✅ Código Seguro (este arquivo)

// textContent trata tudo como texto puro
const filter = location.hash.slice(1);
document.getElementById('output')
  .textContent = decodeURIComponent(filter);

// O mesmo payload:
// → exibido literalmente como string
// → nenhum HTML é processado

textContent escapa automaticamente qualquer HTML — nenhuma tag é criada.

🛡️ Defesas Aplicadas Aqui

✅
textContent em vez de innerHTML O DOM interpreta o valor como texto puro — tags HTML nunca são processadas.
✅
Content Security Policy script-src 'self' bloqueia handlers inline como onerror e onclick.
✅
Sem eval() ou Function() Nenhuma construção dinâmica de código no cliente — sem superfície para injeção lógica.
